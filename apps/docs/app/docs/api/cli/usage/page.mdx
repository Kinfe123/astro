# CLI Usage

The repository exposes a command-line entrypoint and runtime flags.
## Command Purpose
The CLI entrypoint is a developer workflow. This page explains what command-line options exist, what configuration they depend on, and how to verify the command did what the repository says it does.
## How to Run It
Run `pnpm dev` from the project root after dependencies and required environment values are ready.
Install dependencies first with `pnpm install`.
## What the Command Depends On
The command reads environment-backed configuration. Set these values before using large runs or automation.
- `GITPOD_REPO_ROOT`
- `PACKAGE_VERSION`
- `npm_config_user_agent`
- 2 more environment variables appear elsewhere in the project; document them on the page for the workflow that uses them.
## Flags and Options
Use flags to override defaults for a specific run. Prefer the default script first, then add flags when you need a different scale, concurrency level, target, or debug mode.

## Useful Commands
- `dev` runs `turbo run dev --concurrency=40 --parallel --filter=astro --filter=create-astro --filter="@astrojs/*" --filter="@benchmark/*"` and starts the local development workflow.
- `build` runs `turbo run build --filter=astro --filter=create-astro --filter="@astrojs/*" --filter="@benchmark/*"` and creates the production build or compiled package artifacts.
- `test` runs `turbo run test --concurrency=1 --filter=astro --filter=create-astro --filter="@astrojs/*"` and runs verification for expected behavior.
- `format` runs `pnpm run format:code && pnpm run format:imports` and checks or fixes code style before changes are shipped.
- `format:ci` runs `pnpm run format:code:ci && pnpm run format:imports:ci` and checks or fixes code style before changes are shipped.
- `format:imports` runs `biome check --apply .` and checks or fixes code style before changes are shipped.
