# Config

Config explains the responsibility boundary around `core/config`.
## What This Area Covers
Config explains the `core/config` behavior that readers can rely on before they inspect supporting files.
## What It Actually Does
- `validateConfig(userConfig: any, root: string, cmd: string): Promise<AstroConfig>` - Turn raw config values into normalized values
- `resolveConfigPath(options: ResolveConfigPathOptions): Promise<string | undefined>` - Resolve the file URL of the user's `astro.config.js|cjs|mjs|ts` file
- `splitInlineConfig(inlineConfig: AstroInlineConfig)` - `AstroInlineConfig` is a union of `AstroUserConfig` and `AstroInlineOnlyConfig`. This functions splits it up.
- `resolveConfig(inlineConfig: AstroInlineConfig, command: string, fsMod = fs): Promise<ResolveConfigResult>` - Resolves the Astro config with a given inline config. Parameters: inlineConfig An inline config that takes highest priority when merging and resolving the final config.; command The running command that uses this config. Usually 'dev' or 'build'..

## Behavior Notes
- Recognizes package markers such as `srcDir`, `publicDir`, `outDir`, `cacheDir`, `trailingSlash`, `format`, `client`, `server`, `assets`, `serverEntry`, `inlineStylesheets`, `message`.
- Normalizes inputs to values such as `srcDir` -> `./src`, `publicDir` -> `./public`, `outDir` -> `./dist`, `cacheDir` -> `./node_modules/.astro`, `trailingSlash` -> `ignore`, `format` -> `directory`, `client` -> `./dist/client/`, `server` -> `./dist/server/`, and more.
