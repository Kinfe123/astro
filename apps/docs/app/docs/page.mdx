# Astro

Astro is a modern site builder with web best practices, performance, and DX front-of-mind.
## Product Story
Astro is documented as a product with capabilities, workflows, configuration decisions, and integration surfaces. These pages are organized so a reader can understand the purpose of the project before they need to inspect source files.
## Reader Paths
- Start with the overview, quickstart, and installation pages to understand the product before moving into deeper setup details.
- Use feature pages to understand product capabilities surfaced by the README, routes, UI, or domain files.
- Use self-hosting pages when deciding how this project fits into a framework, server, or deployment environment.
- Use configuration pages for runtime settings, environment files, deployment files, database files, or product config.
- Use guides for task-oriented workflows such as CLI usage, local development, troubleshooting, or product-specific operations.
- Use API reference pages after the mental model is clear and you need routes, commands, adapters, exports, or type contracts.
## Documentation Model
Each page answers four questions: what the concept is, when to use it, how a developer or operator completes the workflow, and what to verify next. File paths and exports are supporting context, not the main explanation.

## Common Commands
- `build` runs `turbo run build --filter=astro --filter=create-astro --filter="@astrojs/*" --filter="@benchmark/*"` and creates the production build or compiled package artifacts.
- `dev` runs `turbo run dev --concurrency=40 --parallel --filter=astro --filter=create-astro --filter="@astrojs/*" --filter="@benchmark/*"` and starts the local development workflow.
- `test` runs `turbo run test --concurrency=1 --filter=astro --filter=create-astro --filter="@astrojs/*"` and runs verification for expected behavior.
