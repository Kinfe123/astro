# Deployment

By default Astro produces a fully static site in the `dist/` directory that you can upload to any static host (Netlify, Vercel, Cloudflare Pages, S3, etc.) without any extra configuration. If you need server-side rendering, you add an adapter and deploy the resulting server bundle to a Node.js process or edge runtime.

## Static deployment

Build your site and upload the output:

```bash
npm run build
```

Everything in `dist/` is self-contained HTML, CSS, and assets. Point your host's publish directory at `dist/` and you're done.

## Container-based deployment

The repository's `examples/` directory ships Dockerfiles for every starter template. They all use Node 18 as the base image:

```dockerfile
FROM node:18-bullseye
```

For a containerized Node.js deployment with SSR you would:

1. Add an SSR adapter (`@astrojs/node`, for example) to your config.
2. Run `npm run build` to produce `dist/server/`.
3. Copy the output into your image and start the server with `node dist/server/entry.mjs`.

The dev container in `.devcontainer/Dockerfile` uses `mcr.microsoft.com/devcontainers/javascript-node:0-18` and additionally installs pnpm and Playwright — that image is for contributors to this repository, not for deploying your site.

## Preview before deploying

After a production build you can verify the output locally:

```bash
npm run preview
```

This serves the `dist/` directory through Astro's built-in preview server. It is **not** a production server — use it only to spot-check the build output before uploading.

> **Note:** The preview server does not support SSR. If you're testing an SSR adapter output, run the generated server entry directly with Node.
